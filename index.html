Analytical Thinking 分析四步驟
  • ① 拆解 (Separate $\Sigma$ parts / $\Sigma$ components) 釐清核心問題 (the problem)、市場需求 (the demand) 與關鍵提問 (the question)。
  • ② 深度探究 (Investigate deeply with evidences) 以實證資料為基礎進行深入調查，挖掘各要素之間的潛在關聯 (potential relationships)。
  • ③ 重組架構 (Recombine → Coggle Mind Map) 將拆解後的要素重組為系統化 (systematic)、結構化 (structured) 且流程導向 (process-oriented) 的心智圖。
  • ④ 洞察輸出 (A new representation ⇒ Insights) 透過新的視覺與結構化呈現，產出可落地的商業洞察 (Insights)。
評估標準：有效性 vs. 效率
✓ Effective (有效性)

達成目標與核心目的 (goal / purpose reached)，確保方向正確。

✕ Efficient (單純效率)

僅追求投入產出比 (Output ↑ / Input ↓)，若未達目標則無意義。

PRD 產品需求與 BNA Agent 商業化
PRD (Product Requirements Document) Supply & Demand Functions 功能 Verifications 驗證 IP 智慧財產

將 BNA Agent 轉化為可商業化交易的 MVP (Minimum Viable Product)，以軟體 / App / 網頁形式提供 SaaS (Software as a Service) 服務，為目標客群 (TA) 創造願付價值 (Value / WTP)。

多模態筆記到知識庫與部署流程
  • 1. 多模態素材輸入 (Inputs) 課堂手寫筆記 (In-class hand-written note)、語音錄音 (voice recording)、影片 (video)、圖片 (image/pictures)。
  • 2. AI 代理人協作 (AI Agents) 結合 Chatbot（討論諮詢）、Task Agent（分析與摘要）與 Coding Agent（程式與圖表生成），並融入人類的創造力與批判性思考 (Creativity & Critical Thinking)。
  • 3. 結構化 Markdown 文件產出 (.md) 產出 KB.md（知識庫）、handoff.md（團隊交接文件）與 PRD.md（產品需求文件）。
  • 4. 視覺化與單頁應用部署 (Deploy) 將摘要轉換為 SVG 向量圖表與 SPA (index.html)，最終部署 (Deploy) 為可公開存取的 http:// 網址連結。
